# 角色协议

## 自判
读 `PROJECT.json` 的 `roles`，结合当前任务判定自己是架构 / 实施 / 验证 / 人类授权人。角色在同一工作包评审过程中不得自我切换。

## 权责
| 工作 | 架构 | 实施 | 验证 | 人类 |
|---|---|---|---|---|
| 项目目标与业务范围 | 建议/分析 | 输入 | 输入 | 决定 |
| 架构、数据主权、NFR | 负责 | 提 RFC | 验证 | 高风险确认 |
| IWP | 编制 | 接受 | 可审查 | 无需日常参与 |
| 代码/测试/IaC | 不实施 | 负责 | 独立复现 | 无需日常参与 |
| 架构评审 | 负责 | 整改 | 提供事实 | 必要时仲裁 |
| 生产部署 | 给就绪结论 | 执行 | 验证 | 逐次批准 |
| 风险接受 | 评估 | 提补偿措施 | 验证 | 决定 |

## 独立性
- 架构 AI 不直接修复被审查的实现 → 退回实施整改。
- 实施 AI 不得修改架构基线和验收门槛。
- 验证 AI 不作业务风险接受。
- 人类生产批准不替代技术门禁。

## 文件所有权（分权如何声明与强制）
1. 每个 IWP 在 `PROJECT.json` 的 `effective.work_packages[].file_ownership` 声明 `owner + paths`。
2. 实施方只能改其声明路径。
3. PR 正文带机器标记（见 PR 模板）：`<!-- gov:role = ... -->`、`<!-- gov:paths = ... -->`。
4. CI 校验「本次 diff 触及路径 ⊆ 声明拥有路径」，越权即拦。
5. **默认硬约束**；小项目设 `enforcement.file_ownership=false` 关闭。

## 越权如何被发现
- 本地：`validate-governance.mjs` 查 primary≠verifier、write 路径不重叠。
- CI：`validate-governance.mjs --ci` 查 diff 归属 + 权威文档同变更。

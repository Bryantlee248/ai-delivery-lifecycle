# 领域专家按需加载（正交于治理角色）

> 治理角色（架构/实施/验证/人类）回答「谁有权改什么」；
> 领域专家回答「这个领域怎么专业地做」。两者**正交**，可叠加、不冲突。

## 什么时候用

阶段 3（架构）或阶段 5（实现）中，当 IWP 涉及具体专业领域（安全、前端、UI、性能、数据分析等）时，实施/验证 AI 按需加载对应领域专家作为「知识注入」——**只补专业方法，不改变治理分权**。

## 来源（按优先级）

1. **本地 AAS 库**：用 `skill-index` 搜索（security / ux / performance / frontend 等）。
2. **agency-agents 角色库**：
   - 上游：`msitarzewski/agency-agents`
   - 中文：`jnMetaCode/agency-agents-zh`（含中国平台原创角色）
   - 精选高频：安全工程师、前端开发、UI 设计、代码审查、性能优化、数据分析。

## 加载纪律（防负担）

- 每次只加载当前 IWP 需要的 **1–2 个**，禁止批量加载（全量会带来 token 负担与指令冲突）。
- 领域专家提供「方法/checklist」，**不授予权限**；文件所有权仍按 `role-protocol.md` 执行。
- 领域专家与治理角色叠加时，**治理角色的独立性/边界优先**。

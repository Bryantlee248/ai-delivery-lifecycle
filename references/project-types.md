# 项目类型映射（类型 → 技术栈 / UI / 验收 / 分发）

> 生命周期方法论对所有类型通用（9 阶段 + 机器门不变）；本文把「类型专属」的东西集中映射，
> 供阶段 2（UI 设计）、阶段 3（架构）、阶段 7（验收）、阶段 8（部署）按类型取用。

## 类型总览

| 类型 | 技术栈 ADR（阶段3） | UI 组件库（阶段2 DESIGN） | 验收方式（阶段7） | 部署/分发（阶段8） | 特殊约束 |
|---|---|---|---|---|---|
| **B/S**（浏览器+服务端） | 前端 React/Vue + 后端 Node/Go/Java | shadcn/ui、Ant Design、MUI | Playwright 浏览器走查 | 服务器 + CI/CD | 无 |
| **C/S**（桌面+服务端） | Electron / Tauri / Qt + 后端 | 桌面 UI（Tauri 用 web、Qt 用 QML） | 桌面自动化（Playwright for Electron 等） | 安装包 + 签名 + 自动更新 | 客户端更新、多平台打包 |
| **微信小程序** | 原生 WXML/WXSS 或 Taro / uni-app | Vant Weapp、TDesign | 小程序自动化（minium）+ 真机预览 | 微信审核 + 发布 | 审核规则、包大小、类目资质 |
| **App**（iOS/Android） | Flutter / React Native / 原生 | Ant Design Mobile、Flutter Material | Appium / Maestro + 真机 | 应用商店审核 + 签名 | 商店审核、签名、隐私合规 |
| **CLI / 脚本** | 任意（Node/Python/Go） | 无（终端） | 单测 + 命令级 E2E | 二进制 / 包分发 | 无 |
| **API 服务** | 任意后端 | 无（接口） | 契约测试 + curl/E2E | 服务器 + 容器 | OpenAPI 契约 |

## 各阶段如何取用

- **阶段 2（UI 设计）**：按类型取「UI 组件库」列 → DESIGN.md 的具体参照物与 tokens 来源。
- **阶段 3（架构）**：按类型取「技术栈 ADR」列 → 写 ADR。
- **阶段 7（验收）**：按类型取「验收方式」列 → 用户旅程级验证工具（浏览器/设备/小程序模拟器）。
- **阶段 8（部署）**：按类型取「部署/分发」列 → 环境/组件声明 + 分发方式（服务器/商店/审核）。

## 铁律

- 类型只影响「技术/工具选择」，不影响「生命周期流程」——所有类型都走 9 阶段 + 机器门。
- 轻档紧凑循环同样按类型取组件库（如小程序直接挂 Vant Weapp），但不铺完整 DESIGN.md。
- UI/验收的"具体参照物"仍必须落成可验收契约（DESIGN.md / E2E），工具可换、验收不省。

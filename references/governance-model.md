# 治理模型（三平面 + 阶段门 + 评审分级）

## 三平面（职责分离）
| 平面 | 谁 | 做什么 | 不做什么 |
|---|---|---|---|
| 架构 | 架构 AI / 架构负责人 | 目标架构、边界、契约、工作包(IWP)、评审 | 不直接实现/修复代码 |
| 实施 | 实施 AI | 代码、测试、IaC、部署、证据 | 不改架构基线/验收门槛 |
| 验证 | 验证 AI（可选） | 独立复现关键结果 | 不做业务风险接受 |
| 人类 | 授权人 | 目标、真实权限、生产批准、风险接受 | 不替代技术门禁 |

同一工作包中，架构 AI 不直接修复自己审查的问题。

## 阶段门 G0–G4
| 门 | 检查 | 结论 |
|---|---|---|
| G0 项目可定义 | 目标/范围/非目标/角色/风险等级/五文件 | GO / CONDITIONAL_GO / REDUCE_SCOPE / NO_GO |
| G1 架构可实施 | 架构视图/数据主权/接口/NFR/环境/组件/威胁/测试策略/IWP | 同上 |
| G2 实现可验证 | 代码/测试/契约/扫描/迁移/监控/备份/回滚/证据 | 同上 |
| G3 部署可控制 | 不可变制品/环境/配置/批准/部署/冒烟/观察/回滚 | 同上 |
| G4 运行可持续 | SLO/告警/容量/成本/恢复演练/事件复盘/升级/退役 | 同上 |

阶段门结论只有这四种；条件必须带责任人、期限、验证方式。

## 评审问题分级 P0–P3
- **P0** 严重安全/数据/合规/生产风险 → 立即停止。
- **P1** 核心架构/功能/恢复失败 → 阻断批准。
- **P2** 重要质量问题 → 有条件批准。
- **P3** 非阻断改进 → Backlog。
- 同一 P0/P1 三轮仍不关 → 重新设计 / 缩小范围 / 请求人类决策。

## 标准工作闭环
```
ROADMAP 工作项
  → 架构发 IWP
  → 实施接受/澄清/RFC
  → 实施 + 自检
  → 证据包
  → 架构/独立验证
  → 整改闭环
  → 批准制品
  → 环境部署
  → 运行验证
  → 更新 PROJECT.json / ROADMAP / WORKLOG
```

## 冲突优先级
```
法律/组织政策 > 人类明确合法授权 > GOVERNANCE.md > PROJECT.json 当前有效引用
  > 已接受决策(ADR/RFC) > IWP/契约/基线 > 实施细节 > 聊天和临时说明
```
